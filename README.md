# 🏗️ System Architecture

Cravio follows a modular, layered architecture that separates responsibilities across the frontend, backend, services, and external cloud providers. This approach improves scalability, maintainability, and testing.

---

## High-Level Architecture

```text
                            ┌─────────────────────┐
                            │      Customer       │
                            └──────────┬──────────┘
                                       │
                                       │ HTTPS
                                       ▼
                      ┌────────────────────────────────┐
                      │     React + Vite Frontend      │
                      └──────────┬──────────────────────┘
                                 │
                                 │ Axios REST APIs
                                 ▼
                ┌─────────────────────────────────────┐
                │        Express.js Backend           │
                └──────────┬──────────────────────────┘
                           │
         ┌─────────────────┼─────────────────┐
         │                 │                 │
         ▼                 ▼                 ▼
 Controllers          Middleware          Services
         │                 │                 │
         └─────────────────┼─────────────────┘
                           │
                           ▼
                      Mongoose ODM
                           │
                           ▼
                  MongoDB Atlas Database
                           │
        ┌──────────────────┴──────────────────┐
        ▼                                     ▼
 Cloudinary                           Stripe Payments
(Image Storage)                      Checkout & Webhooks
```

# 🔐 Authentication Workflow

The authentication system uses **JWT Access Tokens** and **Refresh Tokens** stored in **HttpOnly Cookies** to provide a secure and seamless user experience.

```text
                   User

                     │

                     ▼

             Enter Credentials

                     │

                     ▼

          Backend Authentication

                     │

        ┌────────────┴────────────┐
        │                         │

        ▼                         ▼

 Generate Access Token     Generate Refresh Token

        │                         │

        ▼                         ▼

Return Access Token      Store in HttpOnly Cookie

        │
        ▼

Authenticated Session

        │

        ▼

Protected Routes

        │

        ▼

Automatic Refresh on Expiry

        │

        ▼

Generate New Access Token
```

---

# 🍪 Access Token Lifecycle

```text
Login

↓

Access Token Issued

↓

API Request

↓

Token Valid?

↓

Yes ───────────────► Continue Request

↓

No

↓

Refresh Token Exists?

↓

Yes

↓

Generate New Access Token

↓

Retry Request

↓

Success

↓

No

↓

Redirect to Login
```

# 🚀 Getting Started

Follow this guide to set up **Cravio** on your local machine.

Make sure the following software is installed before running the project.

| Software              | Recommended Version   |
| --------------------- | --------------------- |

# 📥 Clone the Repository

```bash

```

---

# 📦 Install Dependencies

## Backend

```bash
cd backend
```

## Frontend

```bash
cd frontend
npm install
```

---

# ⚙ Backend Environment Variables

Create a file named

```text
backend/.env
```

and add the following variables.

| Variable                 | Description                  |
| ------------------------ | ---------------------------- |
| PORT                     | Backend server port          |
| MONGODB_URI              | MongoDB Atlas connection URI |
| DB_NAME                  | Database name                |
| ACCESS_TOKEN_SECRET_KEY  | Secret key for access token  |
| ACCESS_TOKEN_EXPIRY      | Access token expiry          |
| REFRESH_TOKEN_SECRET_KEY | Secret key for refresh token |
| REFRESH_TOKEN_EXPIRY     | Refresh token expiry         |
| CLOUDINARY_CLOUD_NAME    | Cloudinary cloud name        |
| CLOUDINARY_API_KEY       | Cloudinary API key           |
| CLOUDINARY_API_SECRET    | Cloudinary API secret        |
| STRIPE_SECRET_KEY        | Stripe Secret Key            |
| STRIPE_WEBHOOK_SECRET    | Stripe Webhook Secret        |
| CORS_ORIGINS             | Allowed frontend origin      |

Example:

```env
PORT=5100

MONGODB_URI=

DB_NAME=

ACCESS_TOKEN_SECRET_KEY=

ACCESS_TOKEN_EXPIRY=15m

REFRESH_TOKEN_SECRET_KEY=

REFRESH_TOKEN_EXPIRY=7d

CLOUDINARY_CLOUD_NAME=

CLOUDINARY_API_KEY=

CLOUDINARY_API_SECRET=

STRIPE_SECRET_KEY=

STRIPE_WEBHOOK_SECRET=

CORS_ORIGINS=http://localhost:5173
```

---

# ⚙ Frontend Environment Variables

Create

```text
frontend/.env
```

| Variable                    | Description            |
| --------------------------- | ---------------------- |
| VITE_API_URL                | Backend API URL        |
| VITE_STRIPE_PUBLISHABLE_KEY | Stripe Publishable Key |

Example

```env

VITE_STRIPE_PUBLISHABLE_KEY=
```

# ❗ Troubleshooting

## MongoDB Connection Failed

✔ Verify your MongoDB URI.

✔ Ensure your IP is whitelisted.

✔ Check your database name.

---

## Cloudinary Upload Failed

✔ Verify Cloudinary credentials.

✔ Check API Key and Secret.

✔ Confirm upload preset if used.

---

## Stripe Payment Issues

✔ Verify Stripe Secret Key.

✔ Verify Publishable Key.

✔ Configure the Stripe Webhook.

✔ Add the Webhook Secret to the backend environment variables.

---

## CORS Error

Ensure the backend allows requests from the frontend origin.

Example:

```env
CORS_ORIGINS=http://localhost:5173
```

or

```env
CORS_ORIGINS=https://your-production-domain.com
```

---

## Authentication Issues

- Clear browser cookies.
- Verify JWT secret keys.
- Confirm refresh token configuration.
- Ensure HttpOnly cookies are enabled.

# ❓ Frequently Asked Questions

<details>

<summary>Does Cravio support production deployment?</summary>

Yes. The application is designed to be deployed on platforms such as Vercel (Frontend) and Render (Backend).

</details>

<details>

<summary>Does Cravio use JWT Authentication?</summary>

Yes. Authentication is implemented using Access Tokens, Refresh Tokens, and HttpOnly Cookies.

</details>

<details>

<summary>Which payment gateway is integrated?</summary>

Stripe Checkout is used for secure online payments.

</details>

<details>

<summary>Where are images stored?</summary>

Food images are uploaded to Cloudinary and only their URLs are stored in MongoDB.

</details>

<details>

<summary>Is the application mobile responsive?</summary>

Yes. Cravio is fully responsive and optimized for desktop, tablet, and mobile devices.

</details>

# 📡 REST API Overview

## 👤 Authentication

| Method | Endpoint               | Description          |
| ------ | ---------------------- | -------------------- |
| POST   | `/users/register`      | Register a new user  |
| POST   | `/users/login`         | Login user           |
| POST   | `/users/logout`        | Logout               |
| POST   | `/users/refresh-token` | Refresh Access Token |
